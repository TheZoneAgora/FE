1. 큰 그림

진행 중

FE (본인 담당)

Next.js. Sui 지갑(dApp Kit)으로 사용자가 직접 서명 → Vault 컨트랙트 직접 호출. BE 없이도 입출금/조회 가능.
⇄
구현+테스트 완료

Vault 컨트랙트 (진웅)

Move/Sui, Testnet 배포됨. UserVault 자산 보관, 한도 강제, Kill Switch, DeepBook 실행. 60/60 테스트 통과.
미착수

Providing Agent (본인 담당)

시그널 수신 → 인증(backtest/shadow) → Trust Score → AgoraAgent에 검증된 시그널 전달. 팀 배정상 FE와 함께 본인 소관.
⇄
미착수

Web2 BE (형권)

GitHub 레포 0커밋. 스택도 미확정(Node/Flask, Postgres+Redis 논의만). x402 리플레이 저장소, 실행 레코드 DB 등이 여기 속함.

핵심: FE는 BE를 기다릴 필요가 없다. Vault 입출금·조회·긴급탈출·Kill Switch 상태는 전부 온체인 함수라 지갑 연결만 되면 컨트랙트를 직접 호출/조회할 수 있다 (아래 §7 JS SDK 참고). BE/Providing Agent가 필요한 부분(시그널 피드, Trust Score, 리더보드 실데이터)은 지금 없는 게 맞으므로 그 구간만 mock으로 채우고 나머지는 실제 컨트랙트와 지금 바로 연결 가능하다.

4. UserVault 데이터 모델 FE가 화면에 표시할 상태값

Vault는 Sui의 shared object다. 하나의 UserVault<FiatT, CryptoT> = 한 사용자의 볼트 하나.

권한

  • owner — 자산 최종 소유자 (사용자 지갑)
  • agora_agent_operator — 거래 실행 권한을 가진 AgoraAgent 주소
  • agora_agent_status — ACTIVE(0) / REDUCE_ONLY / PAUSED

자산

  • fiat_balance, crypto_balance
  • cost_basis_fiat — 평단가 계산용 원가

한도 (1회 / epoch)

  • max_trade_amount / max_epoch_trade_amount / spent_this_epoch
  • max_crypto_sell_amount / max_epoch_crypto_sell_amount

실행 정책

  • allowed_pool — 허용된 단일 DEX Pool 주소
  • max_daily_fiat_volume / daily_fiat_volume
  • max_position_size, max_loss_amount / realized_loss_amount
  • trading_start/end_minute_utc, max_signal_delay_ms, max_price_deviation_bps

위험도 & Kill Switch

  • max_risk_score_bps — BUY 전용 상한
  • loss_window_ms / max_window_loss_amount / window_loss_amount
  • executed_signals: Table — 중복 시그널 방지

6. 긴급 탈출 UX — FE에 반드시 필요 법적 요구사항

카톡에서 "kill 버튼 없으면 법적 문제"로 명시됨. 두 경로를 명확히 분리해서 노출해야 함:

경로 1

전량 청산 (Liquidate all)

보유 코인을 시장가로 전부 팔아 USDC로. 실현손실 기록되지만 손실 한도로 막히지 않음. min_fiat_output(최소 수령량)을 FE가 실시간 시세 기반으로 계산해서 넣어야 함 — 0 넣으면 안 됨 (샌드위치 공격 경로). 청산 후 자동 정지.

경로 2

정지 + USDC만 회수 (Pause & withdraw)

코인 포지션은 그대로 두고 USDC만 즉시 회수. Agent도 같이 정지. 실제 사용 순서는 "1번(전량청산) → 2번" 조합이 기본 시나리오.

데모 하이라이트: 카톡에서 진웅이 정리한 해커톤 데모 각본은 "나쁜 시그널 라이브 리젝트" + "Kill Switch 라이브 트리거"가 임팩트 포인트로 지정됨. 이 두 버튼/상태 전환이 FE 데모 플로우에서 눈에 띄게 보여야 함.

7. 실행 가드레일 파이프라인 AgoraAgent가 시그널 실행 시 통과하는 검사

FE가 "왜 이 거래가 거부됐는지" 활동 로그에 보여주려면 이 순서와 에러코드를 알아야 함.

  1. Deadline 확인 E_DEADLINE_EXPIRED
  2. AgoraAgent 권한 확인 E_NOT_AGORA_AGENT
  3. Agent 상태 (ACTIVE/REDUCE_ONLY/PAUSED) E_AGORA_AGENT_INACTIVE, E_BUY_DISABLED_IN_REDUCE_ONLY
  4. 시그널 위험도 확인 (BUY만) E_RISK_SCORE_EXCEEDED, E_INVALID_RISK_SCORE
  5. Pool 허용 목록 확인 E_POOL_NOT_ALLOWED
  6. 시그널 중복 확인 E_DUPLICATE_SIGNAL
  7. 시그널 TTL / 거래 가능 시간대 E_SIGNAL_EXPIRED, E_OUTSIDE_TRADING_HOURS
  8. 시그널가 vs 실제 DEX 견적가 편차 E_PRICE_DEVIATION_EXCEEDED
  9. 1회/epoch 한도, 일일 볼륨, 포지션 상한 E_TRADE_LIMIT_EXCEEDED 등
  10. 잔액 확인 E_INSUFFICIENT_BALANCE
  11. DEX 스왑 실행 (DeepBook 또는 Mock)
  12. 최소 수령량 확인 E_MIN_OUTPUT_NOT_MET
  13. 누적 실현손실 한도 확인 E_MAX_LOSS_EXCEEDED
  14. 성공 시에만 한도 사용량 갱신 + OrderExecuted/DeepBookOrderExecuted 이벤트 발생

하나라도 실패하면 트랜잭션 전체가 롤백됨 — 잔액/한도/replay 상태 그대로 유지. "부분 실패" 상태는 존재하지 않음.

10. 아직 없는 것 — FE가 mock으로 채워야 할 구간

  • Providing Agent 서버 — 시그널 수집, backtest, shadow trading, Trust Score 산출. 전혀 없음. FE 리더보드/에이전트 카드는 지금처럼 mock 데이터로 계속 가는 게 맞음.
  • 위험도(risk_score_bps) 산출 공식 — BE와 합의 전. 컨트랙트는 상한 비교만 하고 계산 로직 자체가 없음.
  • Agora↔Providing Agent x402 연결 — 미구현.
  • 실행 레코드 DB (signal ID, payment digest, trade digest 등 이력 저장) — 없음. FE 활동 피드는 당분간 온체인 이벤트 직접 구독으로 대체하거나 mock.
  • AgoraAgent 운영 키/KMS — 미정. 즉, 지금 시점엔 실제 자동 거래 실행을 시연할 운영 주체가 없음 (수동/테스트 트리거만 가능).

→ 결론: Vault 입출금/조회/긴급탈출 UI는 지금 바로 실제 컨트랙트에 연결해서 만들 수 있고, 리더보드/시그널/Trust Score/활동 로그는 당분간 mock 데이터 위에서 UI만 완성해두는 게 현재 백엔드 상황에 맞는 순서.
